Overviewنظرة عامة

From the source (PDF)من المرجع (PDF)

TCP (Transmission Control Protocol) is a reliable transport protocol as it establishes a connection before sending any data, and everything that it sends is acknowledged by the receiver. In this lesson we take a closer look at the TCP header and its different fields.

TCP (Transmission Control Protocol) بروتوكول نقل موثوق لأنه بينشئ اتصال قبل ما يبعت أي بيانات، وكل حاجة بيبعتها بتتأكد من الطرف المستقبل. في الدرس ده هنقرب أكتر لهيدر TCP وحقوله المختلفة.

The fields, one by oneالحقول واحد واحد

From the source (PDF)من المرجع (PDF)
  • Source port: a 16-bit field that specifies the port number of the sender.
  • Destination port: a 16-bit field that specifies the port number of the receiver.
  • Sequence number: a 32-bit field that indicates how much data is sent during the TCP session. When you establish a new TCP connection (3-way handshake), the initial sequence number is a random 32-bit value. The receiver uses this sequence number and sends back an acknowledgment. Protocol analyzers like Wireshark will often use a relative sequence number of 0, since it's easier to read than some high random number.
  • Acknowledgment number: this 32-bit field is used by the receiver to request the next TCP segment. This value is the sequence number incremented by 1.
  • DO: the 4-bit data offset field, also known as the header length. It indicates the length of the TCP header so we know where the actual data begins.
  • RSV: 3 bits for the reserved field. They are unused and always set to 0.
  • Flags: 9 bits for flags, also called control bits. We use them to establish connections, send data and terminate connections:
    • URG: urgent pointer. When this bit is set, the data should be treated as priority over other data.
    • ACK: used for the acknowledgment.
    • PSH: the push function. Tells an application the data should be transmitted immediately, and that we don't want to wait to fill the entire TCP segment.
    • RST: resets the connection; when you receive this you have to terminate the connection right away. Only used when there are unrecoverable errors — not a normal way to finish a TCP connection.
    • SYN: used for the initial three-way handshake and to set the initial sequence number.
    • FIN: the finish bit, used to end the TCP connection. TCP is full duplex, so both parties have to use the FIN bit to end the connection — this is the normal way to end a connection.
  • Window: the 16-bit window field specifies how many bytes the receiver is willing to receive. It's used so the receiver can tell the sender it would like to receive more (or less) data than what it's currently receiving, by specifying the number of bytes beyond the sequence number in the acknowledgment field.
  • Checksum: 16 bits used for a checksum to check whether the TCP header is OK or not.
  • Urgent pointer: these 16 bits are used when the URG bit has been set; the urgent pointer indicates where the urgent data ends.
  • Options: optional, can be anywhere between 0 and 320 bits.
  • Source port: حقل 16 بت بيحدد رقم الـ port بتاع المرسل.
  • Destination port: حقل 16 بت بيحدد رقم الـ port بتاع المستقبل.
  • Sequence number: حقل 32 بت بيوضح قد إيه بيانات اتبعتت خلال جلسة TCP. لما تنشئ اتصال TCP جديد (3-way handshake)، رقم الـ sequence الأولي بيكون قيمة عشوائية 32 بت. المستقبل بيستخدم الرقم ده ويبعت acknowledgment. أدوات تحليل البروتوكولات زي Wireshark غالبًا بتستخدم relative sequence number = 0 لأنه أسهل في القراءة من رقم عشوائي كبير.
  • Acknowledgment number: حقل 32 بت بيستخدمه المستقبل يطلب الـ TCP segment الجاي. القيمة دي = الـ sequence number + 1.
  • DO: حقل 4 بت (data offset)، معروف كمان بطول الهيدر. بيوضح طول هيدر TCP عشان نعرف فين تبدأ البيانات الفعلية.
  • RSV: 3 بت للحقل المحجوز. مش مستخدمة ودايمًا صفر.
  • Flags: 9 بت للأعلام، بنسميها كمان control bits. بنستخدمها ننشئ اتصالات، نبعت بيانات، وننهي اتصالات:
    • URG: مؤشر عاجل. لو البت ده متحط، البيانات لازم تتعامل معاها كأولوية.
    • ACK: يُستخدم للـ acknowledgment.
    • PSH: وظيفة الدفع (push). بيقول للتطبيق إن البيانات لازم تتبعت فورًا، مش هننتظر نملي الـ segment كله.
    • RST: بيعمل reset للاتصال؛ لما تستلمه لازم تنهي الاتصال فورًا. بيُستخدم بس لما يكون في أخطاء مش ممكن استرجاعها — مش الطريقة العادية لإنهاء اتصال TCP.
    • SYN: يُستخدم في الـ 3-way handshake الأولي ولتحديد الـ sequence number الأولي.
    • FIN: بت الإنهاء، بيُستخدم عشان ينهي اتصال TCP. TCP full duplex فالاتنين محتاجين يستخدموا FIN عشان ينهوا الاتصال — دي الطريقة العادية لإنهاء اتصال.
  • Window: حقل 16 بت بيحدد المستقبل مستعد يستقبل كام بايت. بيستخدمه المستقبل يقول للمرسل عايز يستقبل بيانات أكتر (أو أقل) عن طريق تحديد عدد البايتات بعد الـ sequence number في حقل الـ acknowledgment.
  • Checksum: 16 بت لفحص إن هيدر TCP سليم ولا لأ.
  • Urgent pointer: 16 بت تُستخدم لما بت URG يكون متحط؛ بيوضح فين تنتهي البيانات العاجلة.
  • Options: اختياري، ممكن يكون بين 0 و320 بت.
Extra explanation (not from the PDF — a different way to picture it)شرح إضافي (مش من المرجع — طريقة تانية تتخيل بيها الفكرة)
Two quick pictures: think of Sequence / Acknowledgment numbers like page numbers in a book you're mailing chapter by chapter — "I'm sending you pages 1-10" (sequence), and the reader replies "got them, send me page 11 next" (acknowledgment). And think of the six Flags as light switches on a control panel, all off by default, and TCP flips one or two on at a time to say what it wants right now: SYN = "let's start", ACK = "got it", FIN = "let's finish", RST = "abort, something's wrong".
صورتين سريعتين: تخيل Sequence / Acknowledgment numbers زي أرقام صفحات في كتاب بتبعته بالبريد فصل فصل — "بابعتلك صفحات 1 لـ 10" (sequence)، والقارئ بيرد "استلمتهم، ابعتلي صفحة 11 بعد كده" (acknowledgment). وتخيل الـ Flags الستة زي مفاتيح كهرباء على لوحة تحكم، كلهم مطفيين افتراضيًا، وTCP بيولع واحد أو اتنين بس في كل مرة عشان يقول عايز إيه دلوقتي: SYN = "يلا نبدأ"، ACK = "استلمت"، FIN = "يلا نخلّص"، RST = "وقف، في مشكلة".

Summaryملخص الدرس

From the source (PDF)من المرجع (PDF)
  • Minimum TCP header length is 20 bytes (DO = 5), up to 60 bytes with Options.
  • Sequence & Acknowledgment numbers (32 bit each) track exactly how much data has been sent and received.
  • Six flags (URG, ACK, PSH, RST, SYN, FIN) drive the whole lifecycle of a connection.
  • Window size is how TCP's flow control actually gets communicated on the wire.
  • أقل طول لهيدر TCP هو 20 بايت (DO = 5)، وممكن يوصل 60 بايت لو في Options.
  • Sequence و Acknowledgment numbers (32 بت لكل واحد) بيتتبعوا بالظبط قد إيه بيانات اتبعتت واتستلمت.
  • 6 أعلام (URG, ACK, PSH, RST, SYN, FIN) هما اللي بيقودوا دورة حياة الاتصال كله.
  • الـ window size هو الطريقة اللي بيها flow control بتاع TCP بيتوصّل فعليًا على السلك.
